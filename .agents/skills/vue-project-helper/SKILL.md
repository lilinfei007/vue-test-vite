# Vue Project Helper

你正在处理一个基于 Vue 的前端项目。

## Goals
- 帮助用户修改 Vue 组件、页面结构、样式和交互逻辑
- 在尽量少改动的前提下完成需求
- 保持现有项目风格、命名方式和代码组织习惯

## Workflow
1. 先阅读用户当前打开的文件，以及直接相关的组件、样式、接口或配置文件
2. 理解数据流、组件通信方式和样式作用范围后再修改
3. 优先做最小必要修改，避免无关重构
4. 修改后检查是否会影响现有页面结构、样式表现和交互逻辑

## Vue Rules
- 优先遵循项目现有的 Vue 写法，不擅自切换风格
- 如果项目使用 Options API，就优先沿用 Options API
- 如果项目使用 Composition API，就优先沿用 Composition API
- 修改组件时，注意 `props`、`emits`、`refs`、生命周期和响应式数据的兼容性
- 不要随意改动公共组件的对外接口，除非用户明确要求

## Style Rules
- 优先复用现有 class 命名和样式结构
- 修改 CSS 时，尽量只影响当前页面或当前组件
- 注意 scoped 样式、全局样式和样式覆盖关系
- 避免为了小需求大面积重写样式
- 处理布局问题时，同时考虑桌面端和移动端表现

## Project Context
- 遇到页面异常时，同时检查模板、脚本、样式和接口调用
- 遇到构建或运行问题时，可检查 `vite.config.js`、依赖引用和路径别名
- 如果修改接口调用，先确认入参、返回值和错误处理逻辑
- 如果修改工具函数或公共逻辑，注意对其他页面的影响

## Editing Principles
- 保持改动聚焦，不做无关清理
- 保持现有代码风格一致
- 只有在确实提升可读性时才添加简短注释
- 优先交付可直接运行和验证的结果

## Response Style
- 先说明将修改哪些文件和原因
- 完成后简洁说明改动内容、可能影响和验证方式
- 如果存在不确定点，明确指出假设条件
